# Decisions

Decisions made after the [handover](handover.md). Where they differ, this file wins.

## Stack and code style

- **JavaScript, not TypeScript.** Vue 3 Options API + LESS, following Ordner's style:
  - Options API (`name, components, mixins, props, emits, data, computed, watch, methods`).
  - Blank lines inside `<template>`; `</template><script>` and `</script><style scoped lang='less'>` joined; script and style indented 2 spaces.
  - Single quotes in attributes, backticks inside template expressions, `v-bind='{ ... }'` for passing many props.
  - One folder per component with `index.vue`, plus `components/`, `mixins/` and `functions/` subfolders.
  - Imports grouped under comments (`// npm packages`, `// components`, `// local components`, `// mixins`), absolute paths from the project root (`/src/...`, `/foundation/...`).
  - Ordner's own drag-n-drop and tree code is a heavily modified MIT fork and is **not** a style reference; it gets rewritten.
- **Editor engine: CodeMirror 6.** Speed and file fidelity first. No Tiptap prototype.
- **No branch for the spike.** Work happens on `main`; the editor prototype is the start of the real app.

## Shared components (`/foundation`)

- `/foundation` is a local stand-in for the shared `foundation` repo. Code there must not import from `/src`.
- Later it moves to `submodules/foundation` and is shared with Ordner; the move is a Vite alias change, not an import rewrite.

## Drag and drop: one engine, two modes

One pointer-events engine (no HTML5 drag, because of Tauri's file-drop handling on Windows) handles pointer tracking, the dragged-item preview, auto-scroll and hit-testing. It never moves DOM it does not own; it emits a `move` and the owner applies it.

- **Displace mode** (editor blocks, flat lists): items under the pointer move aside to open a gap, like Ordner's list reordering. Built (`foundation/dnd/`): the engine (`index.js`) follows the pointer, moves the preview, auto-scrolls near the scroller's top and bottom edge, and cancels on Escape; the mode (`displace.js`) passes a stretch once the dragged item's top (going up) or bottom (going down) crosses its middle. The mode is a parameter of the engine, so target mode is another mode object.
- **Target mode** (TOC sidebar, trees), built (`foundation/dnd/target.js`): items stay put; the drop position is decided by the **vertical** position over a target node only, never by moving horizontally:
  - near the node's top or bottom edge (20% of its row each, at least 5 px): drop **before** or **after** it, at its level; shown as a thin line on that edge
  - over the rest of the node: drop **onto** it, nesting the dragged node inside (as its first child); shown as a highlight of the target row
  - a node cannot be dropped onto itself or into its own subtree
  - reference: Ordner's sidebar (`ordner/imports/submodules/foundation/client/vue/components/tree/methods/dnd/utils.js`, `getDropPosition`), which works well; it splits the row (the node's own line, not its children) into thirds, top / middle / bottom, so its edge zones are wider than the 10–20% wanted here. Its code is not a style reference (see above), its behaviour is.

## Outline sidebar

- A left sidebar with the document's headings as a tree (relative levels: a `###` under a `#` is one step in). Titles without Markdown; an empty heading shows "Untitled". The row of the section with the cursor has a faint background. Updated when the browser is idle after an edit, never on the typing path.
- **As Ordner's sidebar**: hidden at first; shown and hidden with the Outline button or Ctrl+Cmd+S (macOS "Show Sidebar"): the editor's text slides to where it lands while the sidebar slides in as far as the text moves and fades in, so its edge and the text move as one, at the same speed (and back out), in 0.3 s. Only transforms and opacity are animated: the column takes its width at once and the editor is laid out once; animating the width (as Ordner does) laid out the editor on every frame and stuttered in Safari, Ordner's content sliding only a third of the width ran ahead of the column's edge, and a sidebar sliding its full width moved faster than the text. Its right edge is a 1 px line with a 7 px handle over it; dragging it sets the width live, 160–400 px (Ordner: 100–300; headings are longer than folder names), starting at 240. Width and shown are kept in `localStorage` until the app has a settings store.
- **Slide text with sidebars** (Settings sidebar, off by default, kept in `localStorage`): off, the sidebar is drawn over the editor's left margin and the text stays where it is; the sidebar slides a third of its width and fades. Where the margin is narrower than the sidebar, the text moves right only as far as needed for the sidebar not to cover it (and slides there with the sidebar's edge). On, the sidebar takes its own column and the text moves aside, as described above. The same holds for the Settings sidebar on the right, mirrored; with both shown, the text stays centered where it fits between them, moves aside as far as needed where it does not, and fills the room between them where that is narrower than the text.
- **Rows, as Ordner's**: the pointer cursor over a row (the text cursor over its title's text), and a background fading in over 0.2 s `ease-out` under the mouse: a smaller step than the selected row (light 3% / 6% black, dark 5% / 8% white, after Ordner's #e5e5e5 / #dadada on #ecedee), with a mouse only and not while dragging.
- **Folding, as Ordner's tree**: rows 31 px, nested ones 20 px in, a chevron (23 px) in the indent left of a heading with subheadings, half-faded, turning 90° in 0.2 s when open. The arrow opens and closes; clicking a heading's row goes to the heading (cursor at its text, the heading 32 px from the top), and clicking the row of the heading already selected (the section with the cursor) opens or closes it, at once. **The title's text is a text field to the mouse**: hovering it (and 0.5rem past its end, `@title-reach`) shows the text cursor, and a click there edits the title in place, the cursor where it was clicked (past the end: at the end); the field has no look of its own (same font and place) and is as wide as its text, growing as you type. Enter or a click outside the text saves (a click on another heading's text then edits that heading at once, its cursor where it was clicked; a click anywhere else in the outline, also beside a title's text, only ends editing), Escape cancels, an empty title is cancelled; pressing on the text and moving still drags the heading. The field shows the title as the outline does, so saving a changed title replaces any Markdown inside the heading (bold, links) with the plain text; the `#` marks, closing `#`s and a setext underline stay. The editor shows each keystroke in the heading at once; those changes stay out of the undo history, and when editing ends with a save the original is put back unseen and the final title applied as one change, so a rename is one undo step (Escape, or the title unchanged, leaves nothing in the history). While a title is being edited the outline keeps its list of headings as it was (a title changing in the editor would rebuild the row and its field). A closed heading stays closed under its new title. After Enter or Escape the keyboard focus stays in the outline (it is focusable, for keyboard navigation next); after a click elsewhere it goes where that click puts it. (Double-click to rename was tried and dropped: a click on the selected heading toggles it, and neither waiting to tell clicks apart nor taking the toggle back looked right.) Opening or closing slides the rows below (0.2 s, `cubic-bezier(0.2, 0, 0, 1)`), and the children are a drawer: during the fold their list is the space open so far, with its rows at its bottom and clipped by overflow, so they come out from behind the heading's row and move with the rows below by layout, in the same frames (a separate slide on the compositor drifted in Safari, and any shorter slide moved at a different speed and looked off). On top they fade with their own timing: in as long as the fold but 40% of it later, out almost at once (15% of it, 30 ms) with a strong ease-in, `cubic-bezier(0.4, 0, 1, 1)`, so they are gone before the space closes (fading out more slowly on the fold's ease-out left faint rows in the last of the closing space) (a fade-out held at its end flashed in Safari; faded-out rows are transparent by style until removed). All settings are LESS variables at the top of `outline/components/node.vue` (`@fold-*`, `@fade-in-*`, `@fade-out-*`); Ordner: 0.25 s `ease`, a 1rem slide and a 0.1 s fade out. Everything starts open; closed headings are remembered by id (title, plus which heading of that title it is), so they stay closed through edits and moves; renaming opens it again.
- **Dragging a heading** (after 4 px; less is a click) moves it with its whole section, in target mode: before / after a heading at its level (after = after its whole section), or onto it as its first child (after its own text, at the level of its first subheading, else one deeper). Every heading in the moved section shifts by the same amount. Refused, with no marker: onto itself or into its own section, or any heading deeper than `######`. Markers: a 2 px line on the edge starting with a 9 px ring centered on the row's left edge, where the dropped heading's level starts, and running to the row's right edge (`@drop-line`, `@drop-ring`; Ordner's line has a small triangle at each end, tried at the right end and dropped), a 2 px frame for onto; the dragged row fades to 0.4, and its title follows the pointer as a label below and right of the hand, like a tooltip, with the dragged block's look (opaque background, shadow), so it covers none of the rows it is dragged over (a copy of the row moving up and down over them was tried). A drop onto a closed heading opens it. One undo step, numbered lists counted again, the moved lines slide where they are drawn, the editor keeps its scroll position; Escape cancels.

## Block model

- Blocks are derived from the Markdown structure; no directives, no metadata in the file.
- Headings are optional. A heading owns everything below it until the next heading of the same or higher level.
- Levels are relative: moving a heading in the TOC moves its subtree and shifts all heading levels inside it by the same amount (`#` ↔ `##`, …). Max depth is Markdown's 6 for now.
- **Blocks are item-sized** (Notion-like: every paragraph and every list item is a block; a heading moves together with what it owns). Bigger blocks (a whole list, a whole section) were built, measured and tried, and dropped as not useful.

### Measurements (2026-10-15)

Generated document of 10k lines, Vite dev build (not minified), Chromium in the Claude desktop browser pane on this Mac. Milliseconds, median / p95. "Update" is the synchronous state and DOM update; "frame" runs to the next paint and cannot be below one 60 Hz frame (~16.7 ms).

| Blocks | Count | Load | Full parse + blocks | Typing update | Typing frame | Move update | Move frame |
|---|---|---|---|---|---|---|---|
| no cards (plain CodeMirror) | – | 21 | 119 | 2.9 / 3.9 | 17 / 18 | 4.9 / 5.6 | 17 / 25 |
| item | 6234 | 26 | 108 | 2.9 / 3.6 | 17 / 18 | 7.0 / 7.9 | 17 / 19 |
| element | 2917 | 24 | 96 | 3.3 / 3.6 | 17 / 18 | 5.4 / 6.3 | 17 / 21 |
| section | 642 | 28 | 96 | 3.1 / 3.6 | 17 / 18 | 9.4 / 11 | 18 / 23 |

- Cards cost nothing measurable while typing: they are computed only for the visible lines. Granularity does not change typing speed.
- Typing work (~3 ms) fits easily in a frame; moves take 5–10 ms of work and usually paint in the next frame (p95 up to ~25 ms).
- The first move after opening a large file parses the whole file once (~100 ms for 10k lines). Parsing in idle time after opening would remove that.
- Selection across blocks is native (one CodeMirror document), so it works the same for every granularity.
- **Result: use `item` (Notion-like: every paragraph and list item is a block) as the default.** Still to measure: Safari/WKWebView (macOS), WebView2 (Windows), WebKitGTK (Linux), and a production build.

### Typing latency (2026-10-15)

Measured key press → paint per look (cards, styled, plain CodeMirror, raw contenteditable, native textarea) in the dev panel.

- **Safari / WebKit is the reference**: the macOS app runs in WKWebView. There, plain and styled CodeMirror are as fast as a native textarea. The remaining cost was the cards (arrow keys between blocks, Enter), so cards are drawn as boxes in layers behind the text and lines carry no paint.
- **Chrome on macOS** is late by a frame for most keys even in a native textarea, so it is not optimized for. Windows (WebView2, Chromium) and Linux (WebKitGTK) still need their own measurement.
- Typing never rebuilds the cards: line marks are mapped through edits and the blocks are re-checked when idle.

## Editing

- **Two modes of one editor**, switched with the **Markdown** button (Cmd+Shift+M, later a View menu item), instantly and keeping undo history: **Document** (the default) shows Markdown as plain text, with no symbols and no blank lines between blocks, and Enter/Backspace/Delete work on blocks; **Markdown** shows the file as it is, in one monospace font with no styling (like a plain text field), with Enter/Backspace/Delete as in a text editor. Moving and selecting blocks and the formatting shortcuts work in both. The file is never changed by switching. (A plain textarea view was tried and dropped.)
- **Blank lines between blocks** stay in the file but are hidden on screen while Markdown is hidden: blocks sit right below each other and the cursor skips the gap. The blank line with the cursor (a new block after Enter) stays visible. Enter in a paragraph or heading starts a new block, Backspace at the start of a paragraph joins it to the block above, Delete at the end of a block joins the paragraph below. Taking a list item's mark off (Backspace where its text starts, or Cmd+7 / Cmd+8 turning the item off) makes it a further line of the text right above it: lined up under that text and spaced like list items, so the text does not move; a whole list turned off becomes lines right below each other. In the file the line keeps its item's own indentation (shallower than a Shift+Enter line, which is indented to the item's text; both are drawn the same). Cmd+7 / Cmd+8 on a further line make a Shift+Enter line a sub-item of its item, and put a line whose mark was taken off back at its old level, with the next number. Backspace or Enter in an empty item (after Enter) ends the list instead: the line becomes a paragraph of its own, split off from the list by blank lines; Enter in an empty sub-item outdents as in Markdown. Blank lines inside a list item are hidden too, the paragraph after them spaced like the item's lines. Turning paragraphs into a list makes one tight list; a quoted line made a list item, task or heading loses its quote. The hiding is a state field updated only for the edited lines (about 1 ms per key on 10k lines; recomputing the whole document was 7–10 ms).
- Several blank lines in a row mean the same as one in Markdown (outside code), so collapsing them never changes the document's meaning; the editor still keeps them as they are in the file. **Empty paragraphs**: one or two blank lines between blocks are the normal gap; every two more show as an empty paragraph (an Enter left empty stays as one, also at the end of the file, where the line after the last line break counts as one of the blank lines). It can be selected (Shift+↑/↓ step onto it, it shows selected, in Markdown mode on one blank line per empty paragraph), Backspace or Delete next to it removes it. Other Markdown viewers show a normal gap there. The hidden blank lines at the end of the file are not a place for the cursor (it goes to the last empty paragraph, or the end of the text).
- **Marks stay as typed until the space**: `#`, `##`, `-`, `1.` at the start of a line show as they are (plain text, a paragraph), and become a heading or list as soon as a space follows (`# `, `- `, `1. `).
- **Literal** (Settings sidebar, off by default): normally typing Markdown in Document mode formats (`# ` makes a heading, `*word*` italic). With Literal on, typed text stays exactly as typed: a typed character that would become Markdown syntax is saved with a backslash (`\#`, `\- `, `*word\*`), which Document mode hides. Only characters that would become syntax are escaped; pasted text and Markdown mode are never escaped. Deleting an escaped character in Document mode deletes its hidden backslash too.
- **Minimal look**: the page looks like plain text: no card boxes, no highlight of the block with the cursor, only spacing between blocks.
- **Spacing**: one gap between blocks (paragraphs, a heading and its text, a list and the paragraph after it), equal as seen from text to text (about 25 px baseline to capitals; headings have a tighter line height, 1.3, so their bigger font adds no extra space); headings get more room above. List items sit close together, nested ones as much as first-level ones; a number starts where a bullet does and is drawn at least as wide, so numbers line up with each other and with bullets, and single-digit numbered items start their text where bullet items do, at every level; a list as a whole is spaced like a paragraph, also from a list of another kind right next to it (numbered after bullets). A quote's first bar starts where the text of other lines starts, its text after the bars. A task item shows a round checkbox (a little larger than the text) in the bullet's place, without a bullet; its text starts where other items' text does. (Cards were tried and dropped: they were only useful for measuring.)
- **Dragging blocks** (both modes): a handle of six dots (2 × 3, as the first version; 3 × 3 was tried), 16 px left of the text (no further out than the editor's edge in a narrow window), a sub-item's left of its own bullet, as far in as the sub-item, fades in only while the mouse is around it: from a little left of it up to the text, never over the text and not further out in the margin. While it shows, the mouse is the hand and pressing anywhere there starts the drag. A drag goes exactly where Alt+↑/↓ would take the block, and the drop gives the same file as pressing the keys as often (tested from every line of the sample), as one undo step: paragraphs and top-level items block by block, headings with what they own among sibling headings, sub-items among siblings and into the items around their parent. What is dragged is what Alt+↑/↓ would move from that block, or the selection when the block is part of a selection over several blocks. While dragging, an opaque copy follows the pointer, on a background of its own a little brighter than the page, with a soft shadow beneath and as much room above its text as below (the space between blocks, whatever the space above the block on the page), both fading in over 0.15 s when the drag starts and out over the drop's slide (`@drop-fade-share` of it, ease-out), moving with the block behind its text (above it, the opaque copy hid the landing text, which blinked) (`--color--drag-preview`, `--shadow--drag-preview`; a copy faded to 0.6 was tried), the block's own place is an empty gap that slides to where it would land, and the lines it passes slide aside (CSS transforms on line decorations; the document and layout change only on drop). On the drop the block starts where its copy was and slides into its place (0.15 s, as Alt+↑/↓ moves slide, but ease-out); a cancelled drag (Escape, or a drop at its own place) glides back the same way. The cursor stays on the text it was on. The drop replays the key presses on a copy of just the region they change, about 0.5 ms per step on 10k lines.
- **List kinds after a move**: a bullet item and a numbered item that end up next to each other get a blank line between them (Alt+↑/↓ and dragging). Right under a bullet item, a numbered item other than `1.` would become a line of its text.
- **Tab / Shift+Tab** (Document mode) indent by block: a list item (with its sub-items, or all selected items) nests under the item above, indented as wide as that item's mark, and moves back out with Shift+Tab; the first item of a list nests under the last item of a list of another kind right above it (bullet points under a numbered step), and Cmd+7 / Cmd+8 on a sub-item switch it between numbers and bullets in place (an item's further lines and sub-items shift with its mark, so they stay in it; further lines get no mark of their own); a paragraph becomes a quote, one level more with each Tab (`> > `), one less with Shift+Tab or with Backspace where the quote's text starts (on a further line of the quote, Backspace joins it to the line above). Enter in a quote starts a new, unquoted paragraph after it (Shift+Enter adds a line to the quote). Nested items are drawn under their parent's text, each quote level with its own bar. Numbered lists are counted again (a sub-list from 1). In code Tab inserts indentation, headings stay. In Markdown mode Tab / Shift+Tab indent the selected lines by 2 spaces. Tab never leaves the editor.
- **The cursor stays at the text** of headings, quotes and list items, also numbered ones whose number is visible: clicking the mark or pressing Home puts it where the text starts, and ← (or word ←) from there goes to the end of the line above.
- **Shift+Enter** starts a new line within the block: a plain (soft) line break in the file, no space between the lines. In a list item the line is indented under the item's text (drawn as wide as the bullet or number) so it stays in the item; in a quote it gets `> `; in a heading it acts as Enter (a heading is one line). Backspace at the start of such a line joins it back in one press.
- **Moving sub-items** (Alt+↑/↓ with the cursor in a nested list item): a sub-item swaps with its siblings, keeping its depth, and at the edge of its sub-list goes into the neighbouring parent item (the last sub-item of A moving down becomes the first sub-item of B); at the edge of the whole list it stays. Top-level items, paragraphs and headings keep moving past whole units.
- **Moves slide** (Alt+↑/↓, both modes): every move swaps two neighbouring stretches of lines, and both slide from where they were drawn to their new place in 0.15 s (a fade of the moved block was tried and dropped). The document changes at once; only the drawing is animated (CSS transforms on line decorations), so keys are never held up, and a move during a slide starts from where the lines are drawn at that moment. Positions are read from the drawn lines right before and right after the move, before the browser paints (CodeMirror's own heights can lag behind the page). A stretch out of view does not slide; a drop after dragging does not slide (its gap already showed the place).
- **A block that cannot move bumps** (Alt+↑/↓ at the top or bottom, a heading with no sibling that way, a sub-item at the edge of its list): it nudges in the pressed direction and springs back, by the kind of block: a list item 2 px, a paragraph, quote or code 3 px, a heading (with its section) 4 px for `####` and deeper, 5 for `###`, 6 for `##`, 7 for `#`. A further bump takes longer, as a spring does (by the square root of the distance): 0.26 s for `###`, from 0.16 s for a list item to 0.31 s for `#`, so the key visibly did something; the text is left as it is. Each press restarts it.
- **Numbered lists after a move** count up in order again, in the same undo step: a list keeps its lowest number as its start and each item its `.` or `)`; a list whose items all have the same number (`1.` `1.` `1.`) is left as it is, an item moved into it getting that number too. Whether a list is written that way is decided without the moved item (its other items, at least two, or one when the moved item came from such a list), so `1. x` joined by `1. a` from a counted list counts up. Sub-lists count from 1; a numbered sub-item that ends up first in its sub-list gets `1.` in the move itself, since right under text Markdown reads `2. b` as more of that text, not as an item.
- **Shortcuts**: Cmd+1…6 heading level, Cmd+0 paragraph, Cmd+7 numbered list, Cmd+8 bullet list, Cmd+B bold, Cmd+I italic, Cmd+E inline code, Cmd+K link, Cmd+Shift+X strikethrough (Cmd+X is cut), Cmd+Enter ticks or unticks a task, or makes a list item or paragraph an open task (as in Notion and Obsidian; not Alt+Space, which types a non-breaking space on macOS and is often taken by launchers), Cmd+Shift+M show Markdown (Cmd+M minimizes).
  - The line formats also work with **Cmd+Alt+number**: browsers reserve Cmd+number for switching tabs (Chrome never lets a page have it), so this second set works everywhere. In the app, Cmd+number are native menu items.
  - Not Cmd+Shift+number (macOS takes Cmd+Shift+3/4/5 for screenshots), not Alt+number alone (types characters such as `[ ] | { }` on many keyboard layouts).
## Desktop app (Tauri)

- **Tauri 2**, `src-tauri/`: one window running the web app, the native menu, reading and saving files. Identifier `app.editor` (a placeholder until the name is chosen; it names the settings folder and must be unique in the Mac App Store). Plain JavaScript on the web side; Rust only for what needs the system. `npm run tauri:dev`, `npm run tauri:build` (`.app` and `.dmg`, unsigned).
- **Platform adapter** (`src/platform/`): the only code that imports `@tauri-apps/*`. `tauri.js` in the app, `browser.js` in a browser (development: the file picker to open, a download to save, no menu); both offer the same functions, listed in `index.js`. A later shell (Capacitor, Swift) is another file there.
- **Window**: created hidden and shown once the web app has drawn the document (no white flash; shown anyway after 3 s should the web app fail). The **standard title bar** for now, showing the file name and "— Edited": with the overlay title bar (traffic lights over the content, title hidden) the name would show nowhere; switching is two lines of config when the title-bar buttons come.
- **Toolbar**: a second row under the native title bar (which keeps the file name), 3rem high, over the top of the sidebars and the editor; the text scrolls on under its translucent, blurred background (as Ordner's folder header). Left: hide it (Cmd+Alt+T, View ▸ Show Toolbar), the outline sidebar. Hiding and showing, it slides out at the top and back in, fading, in 0.3 s as the sidebars do, and the sidebars and the text move up or down with its edge (the top inset is the toolbar's height while it shows, 0 while hidden); hidden, only the arrow stays, drawn under the mouse. The sidebars hide with it and come back with it as they were; opening one while it is hidden (Ctrl+Cmd+S) shows the toolbar too. Center: H1–H6 (a menu where the toolbar is narrower than 41rem), bold, italic, strikethrough, code, link, bulleted and numbered list, task; lit where the cursor's text has the format, and a lit inline button (or its shortcut) with the cursor inside removes the format. Right: the Settings sidebar, holding the former dev toolbar's controls. Icons and buttons as Ordner's: stroke icons on a 128 grid (`foundation/icon/`), all with the same stroke and in the same box (about 104 units; the arrow smaller, 56), 1.3rem, no background, only their colour changes.
- **Menu** (`src-tauri/src/menu.rs`): Editor (About, Services, Hide, Quit), File (New, Open…, Close Window, Save, Save As…), Edit, View (Show Sidebar ⌃⌘S, Show Markdown ⇧⌘M, Full Screen), Window. Items send their id to the web app (`runMenu` in `src/app/index.vue`). Undo/Redo are our own items (the system's would undo in the web view, not the editor's history); with the focus in a text field outside the editor (renaming in the outline) they undo there. Close and Quit are our own too, so the app saves or asks first; Cmd+Q and the Dock's Quit are held back in Rust and handed over as `quit`, and the app exits when its window is gone. A shortcut the editor handles itself (Cmd+Z, Cmd+Shift+M, Ctrl+Cmd+S with `preventDefault`) never reaches the menu. Cmd+1…6 as menu items come with the formats.
- **Windows**: the same code; the menu has no app menu there (Exit goes to File), Show Sidebar has no shortcut yet (Ctrl+Cmd+S has no counterpart), the menu bar sits in the window. Built on GitHub Actions (cross-compiling from macOS is experimental). WebView2 comes with Windows 10/11 (the installer can fetch it). To check there: typing latency (Chromium), fonts, Authenticode signing or the Store's MSIX.
- **Builds on GitHub Actions**, one workflow per platform, each started by hand only: on GitHub, Actions → **Build Windows** or **Build macOS** → Run workflow (or `gh workflow run build-windows.yml` / `build-macos.yml`). Each runs `npm test` and `cargo test` before `tauri-apps/tauri-action` builds: `build-windows.yml` on `windows-latest` (`.msi` and NSIS `.exe`), `build-macos.yml` on `macos-latest` (a universal `.dmg`, Intel and Apple Silicon). No release is made: the installers are the run's Artifacts at the bottom of its page (`editor-windows`, `editor-macos-universal`), a zip, kept 90 days. Unsigned: Windows SmartScreen warns (More info → Run anyway); macOS needs right-click → Open, or `xattr -cr Editor.app`. On Windows the Rust tests skip symlinks and permission modes (Unix only). The test fixtures keep their bytes on any checkout (`.gitattributes`; Git on Windows would otherwise turn LF into CRLF).
- **App icon** (the product will likely be called **Textflow**; the identifier and the app's name stay placeholders until it is decided): a page, tilted 5° left, on a light grey plate. On it three blocks stepping in like an outline: at the top a near-black block with a big white T (SF Pro's heaviest, kept sharp) and two short bars, in the middle the dragged block (the strongest blue, lifted and turned, with the 2 × 3-dot handle and the drop line with its ring), at the bottom the lightest blue one; the blues are lensray's three (`#0066FF`, `#4D94FF`, `#99C2FF`). In dark mode the system's dark plate, a dark page, and the T block turns light with a dark T. One description, `.claude/make-icon.py`, writes everything: the Icon Composer document `src-tauri/icons/Textflow.icon` (one layer per colour, groups for the depth), the pictures Tauri bundles (drawn by Icon Composer's `ictool`, shrunk to macOS's 824 px in 1024, sized by `tauri icon`), and `src-tauri/icons/Assets.car`, compiled from the document, which carries the dark, clear and tinted versions. `bundle.macOS.files` puts it into the app's Resources and `src-tauri/Info.plist` names it (`CFBundleIconName`); `icon.icns` stays for older macOS. The `.car` is made by the script and committed, not by `tauri build` (which could compile a `.icon` listed in `bundle.icon` itself): see the handover, "Things learned".

## Files

- Single-file windows first: New and Open replace the window's document (after saving it, or asking).
- **Saving** (`src/app/functions/saving.js`): a document with a path saves itself 400 ms after the last edit (autosave); Cmd+S saves at once, Save As asks where. A new document or a sample has no path and is saved only by Save / Save As. Saves run one after another, each with the text as it is when it starts; a text already in the file is not written. The window's title shows "— Edited" until the file holds the text.
- **Atomic writes** in Rust (`src-tauri/src/files.rs`): a hidden temporary file next to the original, flushed, renamed over it; permissions copied, symlinks followed (the link stays); a folder that cannot be written to falls back to writing in place. The text is written exactly as the editor gives it (BOM, line breaks). Reading refuses files that are not UTF-8.
- **Changed by another app**: every read and save returns the file's modification time and a save passes the one it last saw; when the file changed since, autosave does not overwrite it but stops and says so once, and the next Save asks whether to replace the file. Taking in the other app's changes comes with watching the file.
- **Closing** (window, Cmd+W, Cmd+Q) or replacing the document: pending edits of a file are saved without asking (if saving fails: Close Anyway / Cancel); a new document with text asks Save / Don't Save / Cancel; an emptied new document goes without asking. A failed save keeps the edits and says why once; autosave tries again on the next edit.
- Dropping a file on the window opens it.
- Images later: the `.md` turns into a folder holding the Markdown and its images. [TextBundle](http://textbundle.org) (`Name.textbundle/` with `text.md`, `assets/`, `info.json`) is the candidate format: Bear, Ulysses and iA Writer support it, and macOS shows it as one file.
- Markdown for now; extending it later is allowed if needed.
